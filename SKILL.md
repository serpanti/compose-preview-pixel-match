# Compose Preview Pixel Match

Работай по циклу **замеры → Compose → PNG из Preview → два сравнения → правка → повторный PNG**. Для готового компонента первый рендер служит исходной точкой. Для нового компонента сначала перенеси измеренные правила макета, затем тем же циклом уточни результат.

## 1. Зафиксировать макет и его состояние

- Определи экран или компонент, Figma frame и вариант либо растровый эталон, viewport, тему, данные и состояние. Для анимации зафиксируй момент времени.
- До правок проверь текущие изменения в репозитории. Найди ближайшие Compose-компоненты, токены темы и существующий способ рендера.
- Если есть Figma, считай размеры и правила компоновки для нужного узла до правок. Сохрани PNG того же состояния для визуальной сверки. Для записи замеров используй [Figma и проверку Android](references/figma-and-android.md).
- Если есть только PNG или JPG, измерь размеры, отступы, форму и цвета по изображению. Укажи допущения о плотности, токенах и поведении при изменении ширины. Сохрани эталон как PNG.
- Запроси только недостающий эталон или сведения, без которых нельзя воспроизвести состояние.

## 2. Реализовать или отрендерить целевое состояние

- При создании UI перенеси правила размеров и размещения из макета в Compose. Переиспользуй подходящие компоненты, ресурсы и токены проекта.
- Получи PNG через существующий screenshot-механизм, например Paparazzi, Roborazzi, Compose Preview Screenshot Testing или аналог проекта. При необходимости сделай временный тест или Preview.
- Для всех итераций фиксируй canvas, density, font scale, локаль, направление текста, тему, шрифты и данные. Используй одинаковый кадр анимации.
- Сохраняй эталон, рендеры и карты различий отдельно от исходников. Нумеруй итерации, например `preview-00.png`, `geometry-00.png`, `color-00.png`.

## 3. Сравнить геометрию и цвет отдельно

Сначала сравни изображения без трансформаций при одинаковом canvas. Если отличается плотность экспорта или положение внешней рамки, зафиксируй общий scale и offset X/Y. Применяй те же значения на всех итерациях. Сдвиг самой вёрстки должен остаться видимым на карте.

Из каталога скилла:

```sh
python scripts/contrast_compare.py --reference reference.png --candidate preview-00.png --output geometry-00.png --color-output color-00.png
```

- **Геометрия.** Красное есть только в эталоне, голубое только в рендере, белое показывает перекрытие. Скрипт выводит двоичный и взвешенный IoU, меру расхождения и границы различий.
- **Цвет и прозрачность.** Оранжевая карта подсвечивает отличающиеся пиксели. Скрипт сравнивает альфа-канал и RGB с учётом альфа-канала, выводит долю пикселей выше порога и границы изменений. По умолчанию игнорирует разницу до 8 единиц на шкале 0–255. Порог меняется через `--color-threshold`. Сравнивай изображения в одном цветовом пространстве, например sRGB.
- Скрипт принимает 8-битные нечересстрочные PNG grayscale/RGB/RGBA. При необходимости преобразуй экспорт с сохранением размеров и прозрачности. При сложном фоне используй исходный рендер и значения токенов вместе с геометрической картой.

Сначала проверь canvas и размеры родителей, затем форму, позиции, зазоры, обводку, порядок слоёв и текст. После совмещения геометрии проверь цвет на однородных участках, заливки, прозрачность и цвета текста. Парные контуры часто указывают на сдвиг, а узкая симметричная кайма может быть следствием сглаживания.

## 4. Исправить и убедиться в результате

- Меняй одну связанную группу параметров за итерацию. После каждой правки получи новый PNG и обе карты с тем же порогом и выравниванием. Сравни метрики и визуальный остаток с предыдущим рендером.
- Сначала исправляй общую причину, например неверную ширину родителя или двойной отступ. Если результат стал хуже, откати только свою последнюю правку.
- Заканчивай, когда геометрия и цвет согласованы в пределах обоснованной погрешности рендеринга. Если две контролируемые итерации не улучшили результат, опиши остаток и его причину.
- Проверь итог на Android-эмуляторе, когда важны status/navigation bars, edge-to-edge, IME, вырез, safe-area или вложенные insets. Для изолированного компонента достаточно Preview при воспроизводимом состоянии. Используй [шаги проверки Android](references/figma-and-android.md#финальная-проверка-на-эмуляторе).
- Запусти сборку и проверки затронутого модуля. Удали свои временные тесты и настройки, если они больше не нужны. Покажи финальный рендер и карты, опиши IoU, цветовое расхождение, выравнивание и проверенные состояния.
